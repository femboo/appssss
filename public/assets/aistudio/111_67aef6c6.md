# Leaf Web — справочник по API

Составлено по исходникам `main.py` (FastAPI, 115 маршрутов). Сервер не запускался: формы ответов взяты из кода, поэтому у редких эндпоинтов ответ описан кратко.

## 1. Общие правила

- **Base URL** — адрес вашего сервера (по умолчанию `uvicorn main:app --port 5000`). Все пути ниже относительные.
- **Формат** — JSON; загрузки файлов — `multipart/form-data`.
- **Авторизация** — только cookie-сессия (Starlette `SessionMiddleware`, cookie `session`, подпись `SECRET_KEY`, срок 30 дней). Bearer-токенов нет. Cookie выдаётся в `/api/login/verify` и `/api/register/verify`; клиент обязан хранить её и слать с каждым запросом.
- **Ошибки** — `{detail: ...}`, где `detail` — строка либо объект `{error, message, ...}`. Коды: 400 валидация, 401 `not_authenticated`, 402 нужна подписка или лимит тарифа, 403 бан / не админ / блокировка попыток (`retry_after` в секундах), 404, 409 занято, 429 лимит или кулдаун, 502/503 внешний источник недоступен.
- **Доступ** в таблицах: `—` публично, `S` нужна сессия, `S?` сессия желательна (без неё часть функций недоступна), `A` только админ.

### Объект трека

`{id, source, title, artist, artwork_url, duration, permalink_url}`, `duration` в миллисекундах. Префиксы `id`: без префикса — SoundCloud, `yt_` — YouTube Music, `ym_` — Яндекс Музыка, `up_` — загруженный пользователем файл. В `POST /api/liked` и `POST /api/playlists/{id}/tracks` трек передаётся как есть, обязательно только поле `id`.

### Параметр sort

Для списков треков: `added_desc` (по умолчанию), `added_asc`, `most_played`, `custom` (ручной порядок из `reorder`).

### Объект subscription

`{tier, display_name, status, expires_at, auto_renew, is_paid, limits{max_playlists, max_liked_tracks, downloads_enabled, max_downloads_per_day, max_uploaded_tracks, max_smart_playlists}, ad_free, high_quality_audio, max_linked_accounts, early_access, ytmusic_enabled, ymusic_enabled, features[], shared_from}`. Тарифы: `free`, `lite`, `standard`, `family`.

## 11. Прочее

- **WebSocket `/ws/live`** — клиент ничего не отправляет; сервер шлёт `{type: reload, scope}` по команде админа.
- **HTML-страницы**: `GET /`, `/privacy`, `/terms`. Статика (аватары, фоны, загрузки) раздаётся с `/static/*`.
- FastAPI по умолчанию отдаёт Swagger на `/docs` и схему на `/openapi.json`. Отключения в коде я не нашёл — проверьте на своём сервере, это даст точные схемы ответов.

## 12. Быстрый старт (curl)

```
BASE=http://127.0.0.1:5000

# 1. логин, шаг 1: на почту уйдёт код
curl -c jar.txt -X POST $BASE/api/login -H 'Content-Type: application/json' \
  -d '{"login":"user","gmail":"user@gmail.com","password":"secret1"}'

# 2. логин, шаг 2: код из письма, в jar.txt сохранится cookie session
curl -b jar.txt -c jar.txt -X POST $BASE/api/login/verify -H 'Content-Type: application/json' \
  -d '{"gmail":"user@gmail.com","code":"123456"}'

# 3. поиск и ссылка на аудио
curl -b jar.txt "$BASE/api/search?q=lofi&source=soundcloud"
curl -b jar.txt "$BASE/api/stream/<track_id>"

# 4. добавить в Избранное (id обязателен)
curl -b jar.txt -X POST $BASE/api/liked -H 'Content-Type: application/json' \
  -d '{"id":"123","source":"soundcloud","title":"Name","artist":"Artist","duration":180000}'
```

## 13. Можно ли сделать десктоп-приложение на этом API

**Да.** Всё, что делает веб-версия, она делает через эти же эндпоинты (плеер целиком на стороне клиента: сервер отдаёт только JSON и ссылки на аудио). Что нужно учесть:

1. **Cookie вместо токена.** Держите cookie `session` в нативном HTTP-клиенте (Electron main/`net`, Tauri http-плагин, Python `requests.Session`, .NET `CookieContainer`) и сохраняйте на диск: срок 30 дней, автологин проверяется через `GET /api/me`. Запросы из webview к другому origin лучше не делать: cookie по умолчанию с `SameSite=lax` и может не уйти.
2. **Вход всегда с кодом на почту** (`EMAIL_VERIFICATION_ENABLED = True`). Нужны экран ввода кода, кнопка «Отправить ещё раз» (кулдаун 60 с) и показ `attempts_left` / `retry_after`.
3. **Воспроизведение.** `GET /api/stream/{id}` → `{url}`. Для SoundCloud ссылка внешняя и недолговечная: запрашивать её прямо перед стартом трека. Относительные ссылки (`up_`, `yt_`, `ym_`) дополнять Base URL и отдавать плееру вместе с cookie (через локальный прокси или собственный загрузчик).
4. **Статистика прослушиваний.** Сам `/api/stream` засчитывает прослушивание; для «огонька» дополнительно слать `POST /api/streak/ping` примерно каждые 15 секунд реального звучания.
5. **Источники.** YouTube Music включён, но только на тарифах standard и family. Яндекс Музыка сейчас выключена флагом `YANDEX_MUSIC_ENABLE = False` (503) и требует личный `ym_token`, который передаётся в query-строке.
6. **Лимиты тарифов.** Обрабатывайте 402 и 429: в `detail.message` лежит готовый текст для показа, в `retry_after` секунды до сброса.
7. **Оплата.** `POST /api/subscription/purchase` возвращает `redirect`: открыть в системном браузере, затем опрашивать `GET /api/subscription`.
8. **Офлайн.** Синхронизации и офлайн-режима в API нет. Скачивание только на платных тарифах и с суточным лимитом, поэтому кэш треков придётся делать на стороне клиента.
9. **WebSocket `/ws/live`** для десктопа не обязателен (там только команды «перезагрузить страницу»).
10. **Хрупкие места.** У API нет версий (`/v1`), refresh-токенов и схем ответов (`response_model` не заданы), а поиск и стрим SoundCloud завязаны на неофициальный API с подбором `client_id`. Формат ответов может меняться вместе с веб-версией, поэтому клиент стоит писать терпимым к лишним и отсутствующим полям.

Что стоило бы добавить на сервере, чтобы клиенту было проще: долгоживущий токен устройства (Bearer) вместо cookie, префикс `/api/v1`, `response_model` для основных ответов, абсолютные URL в `/api/stream`.
